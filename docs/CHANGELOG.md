## 2026-11-19（上午 ~ 中午）

### 境外地图可用性

- **Android / 鸿蒙**：境外自动底图改为 **ESRI 街道图**（`server.arcgisonline.com` 走 Akamai，国内可直连）；
  优先级 ESRI → OSM → 高德 → z3 全球图；手动选项新增「Esri 街道图」。
- **iOS**：自动底图改为 **Apple 地图**（MapKit 系统底图，不挂 overlay、不探测、不回退）；手动选项新增「Apple 地图」。
- **修的 bug**：选新加坡却走高德 —— `MapStyle.effective` 用了 **GCJ-02 偏移边界**（纬度下限 0.83°）判断“境内”，
  把整个东南亚算进中国；改用 `SolarTimeMath.isInChinaRegion`（国家码优先，无码则 73–135°E / 18–54°N）。

### 天气（iOS）

- 接入 **Apple WeatherKit**：自动 = WeatherKit → Open-Meteo → 7Timer!；手动可切 WeatherKit / Open-Meteo。
- WeatherKit 的 **App ID capability 只能手工开**（ASC API 拒绝 `capabilityType=WEATHERKIT`），
  开完描述文件即带 entitlement；已写入 CI 脚本的提示里。
- **官方署名**：Apple 要求显示标识图 + 法律页链接；先后试过「卡片页脚 → 卡片底部 → 最终放到设置页「关于」」
  （苹果自己的天气 App 也不在卡片上贴标识）。
- 修的 bug：`loadIfNeeded()` 从未被调用 → 标识 URL 恒 nil → 永远显示文字；WeatherKit 成功后**没落盘** → 诊断显示 Open-Meteo。

## 2026-11-19（傍晚）

### 常用城市：24 个 + 三端顺序统一

- 新增 **开罗**（UTC+2）、**里约热内卢**（UTC−3），22 → 24，P40 类宽度 4 列 × 6 行整、P30 类宽度 3 列 × 8 行整。
- **修的漂移**：iOS 的排列与另两端不同（摩尔曼斯克在第 16 位、中山站/悉尼前后对调）—— 人工同步的必然结果。
- 新增 [tools/check-presets-sync.py](tools/check-presets-sync.py) + CI `.github/workflows/presets-sync.yml`：
  比对三端预设的**数量、顺序、坐标（1e-9）、国家码**，主判据用坐标（鸿蒙境外城市的 presetKey 是空串）。已做负向测试。
- **「南极中山站」换成「昆仑站」**（-80.4169, 77.1161，中国距南极点最近，约 1050 km）：
  中山站每年极昼/极夜各约 1 个月，昆仑站各约 3 个月；且 11 月现在就是极昼，**随时可验证极昼分支**，不必等特定日期。

### 太阳圆盘：上中天方位 + 短昼标签

- **上中天加方位后缀**：北半球 `上中天 11:39 · 正南`、南半球 `· 正北`（英文 `· S / · N`）。
  圆盘是「面朝赤道的竖直平面」投影，用户容易把日出方向看反，直接标出上中天时的方位最直观。
  宽度同步从 11 字符放宽到 15 字符的估算，避免重叠检测漏判。
- **短昼（2–4h）标签重做**（摩尔曼斯克场景）：原先被推到画布左右边缘。
  试错两轮后确认正解 —— **放到圆外即可**，与正常布局镜像：`y = 地平线 + 10`、x 从交点向外步进到「整块在圆外且离弧 ≥6pt」。
  「圆外」与在地平线上方还是下方无关，这是前两轮想漏的关键点。
- 短昼与上中天的间隙用**几何判据**（间隙 < 6pt 或相交才切紧凑行），不再依赖 `shortDayHours = 2` 的硬阈值。

### 桌面卡片（Android）

- **秒数前两个冒号的根因**：秒数用 `Chronometer`（文本固定 `M:SS`），靠 `maxWidth` 裁掉 `M:` 只露秒数，
  余量给多了冒号就漏出来，与旁边独立的 `:` 视图叠成 `::37`。修法：`ClockWidthMath` 把余量压到 **≤1px**（严格小于一个冒号宽）。
- **「没用足空间」的根因不是对齐**：`widget_content` 早已 `center_vertical`；真正原因是**时钟字号相对卡片宽度比首页小**。
  `CLOCK_ROW_SAFETY` 0.90 → **0.97**（与首页 `CLOCK_FIT_SAFETY` 一致），P30 上 98 → 106px。
  已被宽度拟合卡住（`widthLimited=true`），再大需改两列结构。
- 两次失败尝试已记录：运行时 `setViewPadding` 会让逐时行整行消失；手改脚本生成的 XML 插 `weight=1` 的 `Space` 会让桌面报「加载窗口小工具时出现问题」。

### 页头布局（三端）

同一处结构缺陷三端都有，改了四轮才收敛：

| 轮次 | 问题 |
|---|---|
| 1 | 副标题被困在「标题那一列」→ 红米上换行、右端空一片（宽度只占 47%）|
| 2 | 副标题移出成整行 → 行高被齿轮撑大，间距从 2dp 变十几 dp |
| 3 | 行内**底对齐**（比覆盖层改动小）→ 间距回到 2dp，但 GPS 还在齿轮左边 |
| 4 | GPS 移到副标题行，**放进与齿轮同宽的 32/48dp 定宽槽位**居中 → 同一条中轴（实测中心差 **0px**）|

附带：iOS 副标题原来有 `minimumScaleFactor(0.85)`（缩字号），与「不缩字号」原则冲突，已改为截断。

### 设置页按钮层级（鸿蒙 / Android）

「实时跟随GPS」原为浅色次要样式，与下方实心主色的「应用」并存。统一为主按钮样式：
**主操作 = 实心主色 + 白字**；选项 = 浅色胶囊；输入 = 浅色圆角框。iOS 本来就是这样。
