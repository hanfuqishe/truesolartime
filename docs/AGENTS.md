# 协作约定（供 AI 助手与后续会话参考）

本文件记录本仓库长期有效的**协作约定**与**踩过的坑**，目的是让后续会话不必从零摸索。

---

## 1. 子任务（subagent）复用约定

**核心原则：新任务如果与之前某个子任务属于同一主题，直接把增量要求发给那个子任务，不要新建。**

理由：子任务结束后上下文仍在，用 `send_message` 继续时它记得之前的实测数据、文件结构、基线数字；
新建子任务则要重新交代一遍，既费钱又容易漏掉约束。

判断流程：

1. 这个任务跟之前哪个子任务**同主题 / 有承袭关系**（同一批文件、同一套实测基线）？
   - 有 → `send_message` 给那个子任务，只写**增量**（"接着上次的 XXX，再做 YYY"）。
   - 没有 → 新建 `subagent`，把上下文写全。
2. 跨平台同步类任务，优先发给做过同类同步的子任务（它们知道两端的文件结构）。
3. 真机验证类任务，优先发给手上已有测量脚本、且熟悉两台机器 ROM 怪癖的子任务。
4. 只有在「原子任务上下文已太杂」或「主题确实全新」时才另起炉灶。

**主题分组参考**（每轮会话结束后按实际情况更新）：

| 主题 | 需要知道的背景 |
|---|---|
| 字体 / 字重 / 字号 | Noto Sans SC 子集怎么来的、华为是渲染层描粗（`font_weight_scale`）、`CardDensity`/`CardFontMath`/`fitTextStyle` 的结构 |
| 卡片排版 / 档位 / 分隔线 | 四档退化规则（`SmallRowLayout.cityRowTier`）、小组件 `*_default` 两套 id、分隔线只在档 0 上延、地区与线留 6dp |
| iOS / 鸿蒙同步 | 两端目录结构、`ZoneTable`/`GeoRegion`、断言脚本（`Scripts/main.swift`、`tools/core-check.ts`） |
| 城市预设 | 20 城清单、`countryCode` 传递链（Preset → Place → 持久化 → 时区查表） |
| 真机验证 | 像素测量脚本、两台机器的 adb 用法、ROM 坑（见下） |

## 2. 硬性约束（改代码时必须遵守）

- **不要自行提升版本号**。版本号由 `version.properties` + 构建钩子自动递增（Android 打包成功后 +1）。
- **不要执行 git 命令**（除非明确要求）；改完留工作区，由负责人统一提交。
- **iOS 除非明确要求，否则不主动编译**（推送 `ios/**` 会自动触发 CI 打包）。
- **Compose 禁用 `BoxWithConstraints` / `SubcomposeLayout`**：首页宽屏分支是 `Modifier.height(IntrinsicSize.Max)`，
  在里面用会崩。需要测量宽度时用 `onSizeChanged` + `TextMeasurer`。
- 编码：改文件前先确认原文件的换行风格（CRLF/LF）与是否带 BOM，保持原样；中文注释用 UTF-8。
  **不要用 PowerShell 5.1 读写 UTF-8 源码**，会按 GB2312 解码导致整文件乱码（曾发生一次，只能整份重写）。

## 3. 设备与实测

| 设备 | serial | 备注 |
|---|---|---|
| 华为 ELS-AN00 | `MDX0220321044102` | HarmonyOS 4.2 / Android 12；density 物理 530 + override 450；1200×2640 |
| 红米 2312DRA50C | `58f87d90` | Android 16 / HyperOS；1220×2712 @480dpi |

- **所有 adb 命令必须带 `-s <serial>`**（两台可能同时在线，误操作会改到另一台）。
- 账号侧无 root，`run-as` 不可用（release 包），无法直接读写 App 私有数据。

### ROM 坑（实测）

- 华为：「字体粗细」滑杆改 `system font_weight_scale`（正常 **0.79**，不是 1.0），是**渲染层描粗**：
  字形/字距/bbox 不变，只把笔画描粗；`Configuration.fontWeightAdjustment` 恒为 300（与滑杆无关），
  `font_weight_scale_normal` 只是当前值的镜像，**不能当参照**。滑杆「离开页面才提交」。
- 华为：`settings delete` 某些键**不触发刷新**，改完要 `put` 回值或重启 App 才生效。
- 红米：`device_font_scale` 完全不驱动渲染，只有 `font_scale` 生效。
- 红米：`settings delete secure font_weight_adjustment` 不刷新，必须 `put 0` 才回落。

### 验收基线（像素口径，卡片内容区）

| 设备 | 卡片尺寸 | 备注 |
|---|---|---|
| 华为 | 1088×618 @(56,460) | 换 Noto 字体后曾变 648，钉行高后需回到 618 |
| 红米 | 1100×660 @(60,390) | 同上，曾变 678 |

测量工具：解 PNG 像素，量「卡片 bbox + 三段文字带（标签行/日期行/逐时行）的墨迹量与 x 范围」；
逐秒变化的时钟数字不计入不变量比较。

## 5. 已确定的产品决策（避免反复讨论）

- 三端主/次版本号统一，修订号各自独立，不要求一致。
- 卡片显示锁定字号（`fontScale = 1f`），**设置页/页头/页脚保持跟随系统**。
- 卡片使用自带字体 Noto Sans SC 子集（`res/font/card_sans_*.ttf`），以免疫华为描粗；许可证见 `android/FONT-OFL.txt`。
- 顶部标签行四档退化，**按地点名的自然宽度选档**：
  档 0 左右两半（时区 + 地区贴右 ｜ 真太阳时 + 时辰）→ 档 1 隐藏「真太阳时」（时区 + 地区居中 + 时辰）→
  档 2 隐藏 UTC（地区贴左 + 时辰）→ 档 3 再加省略号；`时辰` 永远贴最右。
  **地名一律 12fp，绝不缩字号**（三端统一；缩字号会让同一名字在不同端观感不一，且明显小于正文显得廉价）。
  竖向分隔线**只在档 0** 上延到标签行；档 1/2/3 的标签行在左右栏之外，结构上无法上延。
  选档顺序：先用 12fp 自然宽度试档 0，放不下依次退 1/2/3，四档都放不下才省略号。
- 竖分隔线**只在档 0** 上延到标签行、且顶端与文字上沿齐平；地区与线留 6dp。
- 地区名查不到时：预设城市回退显示城市名，手工/GPS 坐标显示半角 `-`；天气无数据显示 `-`。
- 「是不是中国境内」判定：**有国家码按国家码**（cn/hk/mo/tw），没有才退回 73–135°E / 18–54°N 包围盒。
- 报时：时辰交接 100ms、关键时间开始 500ms，峰值 42%，走通知音频通道。

## 6. 地图底图策略（2026-11 定稿）

### 三端现状

| 端 | 自动底图 | 说明 |
|---|---|---|
| **iOS** | **Apple 地图（MapKit 系统底图）** | `MKMapView` 默认底图、不挂任何 `MKTileOverlay`；`overrideUserInterfaceStyle` 跟随昼夜 |
| Android | 高德（境内）/ **ESRI 街图（境外）** | osmdroid + 自绘瓦片，带「并行探测 + 先换源再降级 + 渐进升级」兜底 |
| 鸿蒙 | 高德（境内）/ **ESRI 街图（境外）** | 同 Android 策略（`Image` + 自取瓦片） |

三端手动选项：iOS `自动 / Apple 地图 / OSM / 高德矢量 / 高德卫星`；Android 与鸿蒙 `自动 / Esri 街道图 / OSM / 高德矢量 / 高德卫星`。
手动模式统一语义：**不探测、不回退、不降级**，失败显示「底图不可用」，出图后自动恢复。
**Google 地图已评估并放弃**：需绑信用卡、GMS 依赖让 APK +3~5MB、国内 GMS 设备少，收益不足以抵消成本。

### 关键机制（Android / 鸿蒙）

- **并行探测**：切城市/换地点时同时探 5 块单瓦片（`OSM z3/z12` + `高德 z12/z10/z3`），整体 **4 秒硬顶**、已知有内容即**提前收工**；
- **渐进升级**：先到先用（通常 z3，几百毫秒），之后**更好才升级**（先比级别、同级再比偏好源），**永不降级**；
  冻结条件：已是「偏好源 + z12」、用户手动平移/缩放过、距首图 >10 秒；
- **先换源再降级**：偏好源该级空白/失败而另一源有内容 → **先换源**，两源都无才降级（修「南极中山站」这类判成国内但高德无图的点）；
- **空白瓦片判定**：32×32 采样、颜色量化到高 4 位，`!海洋 && (方差 < 12 || (色种 < 8 && 方差 < 400))`；
  **整屏全空白**才算一次空白失败（避免误伤沙漠/冰原这类纯色真瓦片）；海洋豁免：色相 185–265°、饱和 ≥0.22、亮度 ≥60 占比 ≥60%；
- **回退后的恢复**：每 5 分钟探测一块 z3 OSM（校验 PNG/JPEG 魔数，防劫持的 200 假页面），成功即切回并清零；
- **手动选择底图**：不回退、不探测、不降级。

### 三个「真机才暴露」的坑（务必保留现有防护）

1. **缩放自激循环**：z3 出图若立刻清掉「上级没瓦片」的记忆 → 弹回 z12 → 仍失败 → 再降 → 再弹，2 秒内可产生数百次状态发布（肉眼即「地图狂闪」）。
   现在要求「安静 30 秒 + 距上次回弹 ≥5 分钟」才允许回弹；程序化改视口后 **2 秒内的失败不计**（只对高德，OSM 的失败是断网证据不能吞）。
2. **地图必须按结论「出生」**：先用默认源建出地图再切源，会清缓存 + 取消在飞请求且不重发 → 表现为「一直转圈，手指划一下才出图」。
   iOS 用 `.id(...)` 强制重建；Android/鸿蒙先探测再建。
3. **UI 只订阅「有效 plan 快照」**：源/级别/是否降级变化才推送，瓦片计数变化不得触发重组。

### 未知态（没有可信定位）

| 项 | 行为 |
|---|---|
| 触发 | 「跟随 GPS 意图」为真 **且** 拿不到 fix（未授权，或授权后 20 秒无 fix）|
| 标准时间 / 昼夜主题 | 用**系统时钟与系统时区**（主题按 `6 ≤ 小时 < 18` 判白天）|
| 真太阳时 / 时辰 / 高度角 / 经纬度 / 天气 / 白昼 | 占位符：`--:--:--` / `--` / `--` / `--` / `--` / `--` |
| 逐时行 | **保留六格**：首格「现在」+ 按系统时间逐小时，温度 `-°`，无图标但保留图标位（行高不变）|
| 太阳圆盘 | 昼/夜各 180°、地平线过圆心、**无太阳点/箭头/日出日落标签** |
| 地图 | 全球视图、**无标记**；iOS 用独立 `UnknownWorldMap`（不挂 overlay、`updateUIView` 空实现）|
| 时间轴 | **轴保留**（色段自然为空，不额外隐藏），只隐藏「现在」圆点 |
| 地名 | 「定位不可用」，可点击跳系统设置 |

原则：**只使用与地点无关的数据**（系统时间、钟点），任何绑定旧地点的数据（坐标、温度、天气）一律占位。

### 已知限制

- Apple 地图样式不可定制，署名必须显示（`MKMapView` 法律链接别遮挡）；
- 高德在境外多为空白瓦片，最终会降到 z3 全球图（有大陆轮廓、无街道）；
- OSM 域名（`tile.openstreetmap.org` / `nominatim.openstreetmap.org`）在国内网络被 **DNS 污染**（实测解析到 Facebook / Dropbox 的 IP）；
  模拟器同样如此，因此**鸿蒙模拟器可用于验证兜底链**（open-meteo 仍直连可用）；
- ESRI（`server.arcgisonline.com`）走 Akamai，国内可直连 —— 这是「境外底图」能用的关键；若哪天换 CDN 或被封，需要备用方案（自建 Workers 代理）。

## 7. 「是不是中国」有两套边界，绝不能混用（2026-11 踩过的坑）

代码里存在**两个语义完全不同**的「中国」判断，名字都很像，混用会造成真实 bug：

| 边界 | 常量 | 范围 | 唯一用途 |
|---|---|---|---|
| **GCJ-02 偏移边界** | `CoordinateTransform.isInChina` | 经度 72.004–137.8347、**纬度 0.83–55.83** | **只**用于「坐标要不要加 GCJ-02 偏移」 |
| **时区 / 区域边界** | `SolarTimeMath.isInChinaRegion(lat, lon, countryCode)`（iOS `GeoRegion.isInChina`、鸿蒙 `SolarTimeMath.isInChina`） | 有国家码只看 `cn/hk/mo/tw`；无国家码退回 **73–135°E / 18–54°N** | 时区归属、**选哪个底图**、任何「境内/境外」判断 |

**事故**：`MapStyle.effective` 图省事直接调了 `CoordinateTransform.isInChina`，而它的纬度下限是 0.83°，
把整个东南亚都算成「境内」→ 新加坡 / 吉隆坡 / 雅加达 / 马尼拉全部走高德（境外空白）→ 一路降级到 z3 全球图。

**规则**：

1. 任何「境内/境外」判断**只准**用 `SolarTimeMath.isInChinaRegion(...)`（带 `countryCode`），**不准**用 GCJ 边界；
2. 国家码要**一路带下去**：`Place.countryCode` → `MapFallbackState.countryCode` → `BasemapProbe` / `plan()` / 诊断文案，
   否则无国家码时就退回包围盒（虽然能兜住，但会丢掉「新加坡属于境外」这类信息）；
3. 新写边界判断时，**函数名里带上用途**（`needsGcj02Offset` / `isInChinaRegion`），别都叫 `isInChina`。

## 8. 太阳圆盘的标签布局（三端必须逐像素一致）

### 规则

| 半球 | 日出 / 日落标签位置 | 对齐 |
|---|---|---|
| **北半球** | 地平线**上方**、圆的两侧外侧 | 左标签右对齐、右标签左对齐（各自向圆外延伸） |
| **南半球** | 地平线**下方**、圆的两侧外侧 | 同上（日出在右、日落在左，镜像） |

**为什么南半球放到地平线下方**：南半球的昼弧在上半圆、夜弧（虚线）在下半圆；把标签压到地平线之下、圆的左右外侧，
就**几何上不可能压到弧线**。这比「先摆好再检测重叠、再退让」更根本 —— 后者依赖文本宽度估算，估小了就漏判。

### 近极昼 / 近极夜（昼长 22–24h 或 0–2h）

两个时间几乎相同（例如南极中山站 11/19：白昼 22h42m，日出 00:21、日落 23:39），两个交点会挤在圆的同一端，
`sweep ≈ 360°` 使弦退化成一点。此时：

- 两个标签**分别贴到画布左右内边距**（仍遵守上表的「上/下」规则与「向外对齐」）；
- 水平间距 **≥ 卡片宽度的 60%**；
- 「上中天」保持圆顶上方，若与两侧标签相交则上移到顶部内边距。

### 不变量（回归红线）

1. **北半球的锚点不得因南半球改动而变化**（用固定输入的精确坐标断言）；
2. 三个标签的矩形**两两不相交**（任何半球、任何昼长）；
3. **极昼 / 极夜**不画日出日落标签，只画一行「极昼」/「极夜」（极夜连「上中天」也不画）；
4. 标签永远在**交点外侧**、向圆外延伸 —— 不能出现在圆心附近。

> 2026-11 事故：南极中山站（近极昼）时 `日出 00:21` 与 `日落 23:39` 两个标签在圆底重叠成一团，
> 因为当时只按「交点 y」摆位，`halfWidth ≈ 0` 让两者都落到 `cx ± gap`。三端同源，一起修。

### 顶部标签行的字号（三端铁律）

- 地名**恒为 12**（Android 12sp / iOS 12pt / 鸿蒙 12fp），**不因名字长而缩小**；
- 放不下只做两件事：**退档**（收掉真太阳时 → 收掉时区 → 省略号），以及最后用省略号截断；
- 事故背景：鸿蒙曾在四档重构后仍按**半栏宽**计算可用空间（当时档 1/2/3 已改成整行宽），
  导致「香港特别行政区油尖旺区」这种放得下的名字被缩到 9fp；随后又短暂引入过「12 → 9fp 逐档缩」，
  最终三端统一为**不缩字号**。

## 9. 异步查询：用「按地点换代」而不是「全局单飞」（2026-11 踩过的坑）

地名反查、地图瓦片、天气取数这类**按地点发起**的异步请求，三端都踩过同一个坑：

```
❌ 全局单飞（inFlight 布尔）
   请求 A 卡住（境外 Nominatim 12 秒）→ inFlight 一直 true
        ↓
   用户换到另一个城市 → 新请求被 if (inFlight) return 静默拒绝
        ↓
   表现为「跟随 GPS / 换城市后地名半天不出来」
```

**错在哪**：把「并发保护」和「请求去重」混成一个全局锁。而这两件事的粒度完全不同：

| 目的 | 正确粒度 |
|---|---|
| 并发保护 | **同一地点**的去重（6 秒窗口内不重复发） |
| 结果正确性 | **按请求代号（generation）丢弃过期结果** |

### 正确写法

```swift
generation += 1
let myGen = generation              // 新地点换代
// 直接发请求，不看别的请求是否在飞
request { result in
    guard myGen == generation else { return }   // 过期结果丢弃
    finish(result)
}
```

要点：

1. **新地点一律直接发**，不因上一次在飞而阻塞（换地点连查询方都可能变：境内高德 / 境外 OSM）；
2. 旧请求能取消就取消（`disconnect()` / `cancel()`），**取消不了也没关系** —— 靠 generation 兜底；
3. `inFlight` 只允许用于「同一地点、同一代」的状态标记，**不得跨地点阻塞**；
4. **首次 GPS fix 必须自己触发反查**：`applyFix` 里更新 place 后要直接调反查 ——
   曾经只有「手动选城市」那条路径会触发，跟 GPS 时压根没发请求；
5. 超时要短：查询整体 6 秒、单一数据源（高德）5 秒就转兜底，不要干等 20 秒；
6. 诊断里必须有 **耗时 / 请求次数 / 距上次反查 / 跳过原因** —— 否则「没出名字」永远无法定位是网络、节流还是没触发。

### 配套的节流规则（三端统一）

地名反查**不按时间窗口限流，按空间距离**：与「上次成功反查的坐标」相距 **≤ 5 km 且未超过 30 天** 就沿用缓存，
`> 5 km` / 过期 / 距离未知才重查；**换城市 / 手输坐标**走 force 立即查；GPS 采样 **60 秒一次**。

> 事故：Android 与鸿蒙都用过全局 `inFlight`，导致「上一次查询卡住 → 换城市也不查」；
> 同时 Android 的 `applyFix` 从未触发反查。iOS 因为早有 generation 机制没中招。

## 11. 发布（手动，禁止自动触发）

`tools/release-android.ps1` 把 `dist/` 里最新的 Release APK 发到 GitHub Releases。

**它只在用户明确要求「发布到 GitHub」时才运行**：不要接进 CI、不要放进构建流程、
不要在批处理里顺手调用 —— 发版是需要人确认的对外动作。

脚本自身的两道闸：
- `-DryRun`：只打印会发什么（不需要 `-Yes`），用来核对版本号 / tag / 说明；
- `-Yes`：真正的发布开关，不加就退出码 2，什么也不做。

固定的几件事（历史上都踩过）：
- **资源名强制 ASCII**（`truesolartime-android-<ver>.apk`）—— 中文名经 GitHub 上传接口会被编码破坏，
  实测变成 `-.-1.4.225.apk`；
- 说明默认取「上一个 tag 以来的提交」，也可 `-NotesFile` 指定手写版；
- 发布后**走代理下载一次并比对字节数**（国内直连 GitHub 下载常超时，`-Proxy` 传本地代理）。


## 10. 视觉对齐要同时给出「尺寸差」和「位置差」（2026-11 踩过的坑）

要求两个元素「对齐」时，**只说一个维度必然返工**。页头那次连续返工三轮：

```
❌ "把标题字号调大，使之与齿轮等高"     → 高度对上了，但齿轮仍看着高高在上
   根因：对齐的是 IconButton 的 48dp 盒子，图标 24dp 在盒内**居中**，
         盒子底边与标题底边齐平，图标底边却高了 12dp
✅ "标题与齿轮：① 高度差 ≤2dp ② 底边差 ≤2dp" → 一次改对
```

### 规则

1. **给两组数**：`尺寸差`（高度/宽度）+ `位置差`（哪条边或哪个中心对齐）；
2. **指明对齐的是「字形/图标本身」还是「它的容器」** —— 容器有 padding、图标在盒内居中时，
   两者差出 6–12dp 是常态；
3. 用 `uiautomator dump` / `uitest dumpLayout` 取**节点 bounds** 做验收，不要靠肉眼；
4. 判定标准写进断言或提交记录，后续改动才守得住。

### 对齐的稳定实现方式（优先顺序）

| 优先级 | 做法 | 说明 |
|---|---|---|
| ★★★ | **用布局表达意图**：`Box(contentAlignment = BottomCenter)` / `Row(alignItems = Bottom)` / `HStack(alignment: .bottom)` | 元素尺寸变化时自动重新对齐 |
| ★★ | 容器内放一个定宽/定高槽位、槽内居中 | 适合「徽标与图标同轴」这类需求 |
| ★ | 用 padding/offset 补偿魔法数字 | 最后手段；**必须写注释说明它是补偿值**，字号一变就要重算 |

> 事故：鸿蒙用 `padding({ top: 12, bottom: 0 })` 补偿（能对齐但脆弱），Android 用
> `Box(contentAlignment = BottomCenter)`（意图直白、尺寸变化自适应）。后者才是该推广的写法。

### 图标类元素：必须比「墨迹」，不能比「节点框」

`uiautomator` / `uitest dumpLayout` 给出的 **bounds 是节点框**，而图标字体（`SymbolGlyph`、Material Icons、SF Symbols）
都有 em 框内边距，**字形只占 70–85%**。用 bounds 验收会漏掉真实偏差。

> 2026-11 事故：鸿蒙页头的标题与齿轮节点 bounds 底边都是 297px、看着完美对齐，
> 但像素墨迹是「标题 190..283（高 94）/ 齿轮 223..293（高 71）」——
> **标题比齿轮高 32%，齿轮还低 10px**。用户一眼就看出来了。

**规则**：

1. 图标与文字的对齐，验收必须量**墨迹**：截 PNG，按阈值（如 `R+G+B < 450`）取非背景像素的 y 范围；
2. 两项指标同时满足才算对齐：**墨迹高度差 ≤4px**、**墨迹某一边（底边/中心）差 ≤2px**；
3. 调整顺序：**先定字号让墨迹高度接近，再调 padding / 对齐把边对平** ——
   顺序反了会来回改；
4. 记录实测值（两个墨迹范围的 y 值），后续改动才守得住。
