# 关于桌面卡片「非本地时间实时显示」能力的建议（鸿蒙版真太阳时）

- 反馈类型：功能建议 / 能力缺失
- 涉及能力：ArkTS 卡片（Form）与互动卡片（Live Form）
- 应用：真太阳时（Android 版已上架；鸿蒙版同期提交）
- 实测环境：HarmonyOS NEXT 6.0.0（API 20）模拟器 + 真机
- 适用对象：HarmonyOS 应用与卡片开发

## 一、我们做的是什么

「真太阳时」是一款以太阳为准的时钟应用：显示当地**真太阳时**（= 当地标准时间 + 经度修正 + 均时差）与十二时辰，并标注「关键时间」。

Android 版已经开发完成，提供与 App 首页同款版面的桌面小组件：左侧当地标准时间，右侧真太阳时，**精确到秒、每秒自走**，另有当日天气、温度区间、关键时间时间轴与逐时预报。

鸿蒙版已按同一套功能完成开发（首页大卡片、太阳轨迹、位置地图、区划名反查、关键时间配色、代理提醒等），但**桌面卡片**这一块被系统限制卡住，最终只能关闭入口、暂不提供给用户。为了让两个平台体验一致，特此反馈。

## 二、具体卡在哪里

需求和系统自带的时钟卡片一样朴素：**卡片上有一个数字，每秒（至少每分钟）自己走**。但真太阳时不是本地时间，它与本地时间之间有一个由经度和均时差决定的偏移量。我们在 HarmonyOS NEXT 6.0.0（API 20）上逐条尝试，全部受限：

| 尝试 | 结果 |
| --- | --- |
| 卡片内 `TextClock().format('HH:mm:ss')` | `format` 被忽略，始终按系统设置显示到分钟 |
| 卡片内 `TextClock({ timeZoneOffset: ... })` | `timeZoneOffset` 被忽略，始终是系统本地时间 |
| 卡片内 `setInterval` / `setTimeout` | 编译期直接报错：`11706006 can't support form application` |
| 卡片内 `TextTimer({ count: 真太阳秒数 })` | 忽略 `count`，从 `00:00` 开始且不自走（截图验证） |
| `form_config.json` 的 `updateDuration` | 最小粒度 30 分钟（schema 原文：unit is 30 minutes） |
| `form_config.json` 的 `scheduledUpdateTime` | 只能定点，做不到「每分钟」 |
| 卡片可见时刷新（`onFormVisible` 一类回调） | 实测无回调，无法在“用户正看着桌面”时补一次数据 |
| 互动卡片（`LiveFormExtensionAbility`，API 20） | 激活态**最长 3500 ms**，需 `requestOverflow` 申请，桌面上的任何操作都会立即打断，无法作为常驻显示 |

> 补充：解包自编译的 `ets/widgets.abc` 可以看到 `HH:mm:ss`、`timeZoneOffset`、`format` 这些字符串都在包里，说明不是编译期裁剪，而是卡片渲染侧运行时丢弃。

结果：卡片上的真太阳时只能靠“应用在前台时每分钟推一次 + 系统每 30 分钟兜底”刷新，**用户不打开应用时最坏滞后 30 分钟**。一个会显示滞后时间的时钟卡片对用户是误导，所以我们宁可不提供。

## 三、这不是我们一家的需求

「非本地时间 / 偏移时间 / 实时倒数」在卡片上是普遍需求，受同一限制影响的有：

- 真太阳时、恒星时、地方平太阳时等天文/地理时钟；
- 第二时区、跨时区会议时钟（卡片上常要显示“对方时间”）；
- 日出日落、潮汐、极光预报的实时倒计时；
- 股票/加密货币行情、航班动态等需要秒级或分钟级刷新的数值；
- 番茄钟、倒计时、比赛计时等计时类卡片。

Android 上的对应能力是：`AppWidget` 有 `updatePeriodMillis`，配合每分钟的 `AlarmManager` 自刷新与任意格式的 `TextClock`/`Chronometer`，这类卡片很容易实现。

## 四、希望系统补充的能力（按优先级，任一即可解决我们的问题）

1. **`TextClock` 支持 `format` 与 `timeZoneOffset`**（或新增一个“偏移时钟”组件）。
   改动最小、覆盖面最大：卡片里就能自走任意偏移量的时钟，功耗与系统自带时钟卡片一致，不需要提供方做任何后台工作。**我们最希望先有这个。**
2. **放开卡片内的 `setInterval`/`setTimeout`**，或提供“卡片可见期间允许秒级/分钟级定时”的能力（可配合屏幕点亮、前台可见、热档位等条件做功耗约束）。
3. **提供“卡片进入可见”的回调**（我们试过 `onFormVisible`，未生效），让提供方能在用户查看桌面时刷新一次。
4. **放宽周期刷新粒度**：把 `updateDuration` 的最小单位从 30 分钟放宽到 1 分钟，或允许提供方申请“高频刷新卡片”白名单（配合功耗与热档位限流）。
5. **互动卡片支持更长的激活态**：目前 3500 ms 上限（系统应用可豁免）让三方应用无法做“点开后保持实时”的卡片；若能在功耗允许时给三方应用一个更长的窗口（例如卡片可见期间保持激活），也能解决一部分场景。

## 五、复现方式（供验证）

1. 用 DevEco Studio 新建一个 ArkTS 卡片，`form_config.json` 里 `"updateDuration": 1`；
2. 卡片页面写 `TextClock({ timeZoneOffset: -480, format: 'HH:mm:ss' })`
   —— 期望显示另一个时区的时间，实际显示系统本地时间且只到分钟；
3. 卡片页面里加 `setInterval(() => {}, 1000)` —— 编译报 `11706006`；
4. 卡片页面里用 `TextTimer({ isCountDown: false, count: 3600 * 1000 })` —— 显示 `00:00` 且不走。
