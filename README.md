# 真太阳时

一个显示**真太阳时**（真太阳时 / 视太阳时）的跨平台应用，Android、iPhone 与鸿蒙（HarmonyOS NEXT）三端实现。

真太阳时的定义很简单：**太阳经过观测者所在子午线（正南或正北）的那一刻，记为 12:00**。它与钟表时间（北京时间）的差异来自两项修正：

- **经度修正**：取决于观测者所在经度，与东经 120° 每差 1° 即为 4 分钟。这是主要项，在中国境内可达 ±2 小时（乌鲁木齐约 −129 分钟）。
- **均时差**：取决于太阳的视位置（地球轨道偏心率与黄赤交角），全年在 −14 ~ +16 分钟之间。

所以「你在哪」决定了大头，「太阳在哪」只带来十几分钟的微调，两者合起来才是真太阳时。

## 功能

- **实时真太阳时**：每秒刷新的大字时钟，按当地经度与均时差校正。
- **首页大卡片**：与桌面小组件同款版面——左右两栏并排显示「当地标准时间」与「真太阳时」，左栏左上角是 `UTC+8` / `UTC-5` 这样的时区标签、右上角是反查到的行政区划，右栏右上角是时辰与时初／时正；下面一行是日期、当日天气与温度区间（右侧贴经纬度），再往下是 0–24 时时间轴与未来 6 格逐时预报。时间轴上的关键时段色带一直画着（Cold or Mild 绿、Hot or Mild 红），真太阳时真正落在其中时，数字与时间轴上的圆点再一起换成该时段的配色。底色按昼夜切换：白天暖橙、白字，夜里深蓝、金字（两版一致）。
- **十二时辰**：按真太阳时划分（子时自 23:00 起，每两小时一个时辰），大卡片右上角显示当前时辰与时初／时正。
- **太阳位置**：日出、正午、日落按**所在地的法定标准时**显示（中国境内即北京时间，出国或手工指定外地坐标时换成当地标准时），并附真太阳时对照；同时给出太阳高度角与日出到日落的位置弧线，极昼／极夜会单独提示。
- **定位方式**：默认持续跟随 GPS——**应用打开期间每分钟取一次，桌面卡片可见时每 5 分钟取一次**（两者都只在跟随模式下生效）；也可手动输入经纬度、从常用城市快速选择。位置会被记住。**跟随 GPS 但还没有拿到有效定位时，界面与小组件都不显示真太阳时**（显示 `--:--` 与「等待 GPS 定位…」，也不显示区县名），避免用默认坐标冒充当前位置；但**天气位与逐时格子不隐藏、而是画占位符**（`11月14日 周六 · --`、逐时格 `?` + `--`）——早先整块隐藏时，卡片会只剩两个时钟、下面空一大片，看着像坏了。一旦拿到定位立即恢复。**没给定位权限时不算「跟随 GPS」**——与 App 内一致（App 也只在 hasPermission() && source != MANUAL 时才开启跟踪），此时两边都按已保存的坐标（首次安装内置的默认坐标）照常显示，不会出现「主页有内容、桌面卡片却全是占位符」的割裂。
- **位置地图**：内嵌地图，标注当前坐标，支持缩放拖动。默认「自动」——境内用高德矢量（中文地名、路网更细），境外用 OpenStreetMap；设置面板里也可以手动指定 **OpenStreetMap／高德矢量／高德卫星**（两版同一组选项，卫星图同样是无 Key 的栅格瓦片）。高德底图是 GCJ-02 坐标，标点前会做偏移，数据层始终是 WGS-84。
- **时辰交接提醒**：可开关，**进入下一个时辰的那一刻**蜂鸣一声（**250 ms**，比关键时间报时更短，便于区分；开机后自动重新排程）。同样只响提示音、不发通知。若这个落点正好也是某段关键时间的起点（例如真太阳时 15:00），交接会**主动让位**、顺延到下一个时辰——撞车时只响较长的那一声（500 ms 的关键时间报时），不会叠成怪音。
- **桌面小组件**：默认 **5×1** 布局（可双向拖拽缩放），左侧显示所在城市、所在地的标准时间（标签即 `UTC+8` 这样的时区偏移，取观测点的法定时区而不是手机所在时区）、日期与星期，右侧显示当地真太阳时、时辰与时初／时正、经纬度；时间精确到秒、秒数为半高小字。底色与首页大卡片同一套：白天橙色、夜间深蓝，真太阳时与关键时段的配色也按昼夜取两档。标准时间的时分秒由布局里的 `TextClock` 自己驱动（宿主进程按整分／整秒走时，与系统时钟同刻进位，不依赖 App 的刷新闹钟），真太阳时含秒级偏移只能每「真太阳时整分」刷新，秒数由 `Chronometer` 自走：刷新时把它的 `base` 设成「当前真太阳时整分的时刻」，它每次走完都会按 `base` 重算到下一整秒的延时，因此永远落在整秒边界上、不会累积漂移（`ViewFlipper` 的 `postDelayed(1000)` 每秒要多花几十毫秒，一分钟能慢近两秒）。`Chronometer` 的文本是 `M:SS`，于是用 `setMaxWidth` 把宽度限成两位数字、配合右对齐，只露出秒数；保留半高小字的样式。这里有两个要点：字体必须是**等宽**的（等宽下 `0:` 与 `00` 同宽，切点才与字体缩放、密度无关），字号也由 App 以 **px** 下发（布局里的 sp 会由宿主按它自己的字体缩放解析，一旦与本进程的度量不一致，裁剪点就会偏，把冒号也露出来——表现成「秒前面两个冒号」）。刷新落在整分边界之后 30 ms，肉眼看来就是「秒数跳到 00 的同一刻」。秒数的 `base` **不是每分钟都重发**：`Chronometer` 内部用 `Math.round((now - base) / 1000f)` 换算秒数，若在某一秒的后半段重设 `base`，那一秒会被压短、下一秒被拉长（看上去就是「秒忽大忽小」），所以只在基准相位真的变了（换位置导致偏移变化、进程重启、视图重建、布局切换）时才重发。每分钟的时分刷新靠一个**唤醒型**闹钟：排在整分边界之后 30 ms，一响就刷新，而且**刷新之前先把下一分钟排好**（排程要是写在刷新之后，一次异常或进程被冻结就会让链条彻底断掉，分钟停在旧值）。小米/红米/华为/荣耀这类系统会冻结后台应用，息屏后连唤醒闹钟都可能被吞掉（实测 HyperOS：睡 3 分钟后排好的下一次刷新直接从系统闹钟列表里消失），因此这几家改用 `setAlarmClock()` 语义排程（会出现在系统的「下一个闹钟」里），其余机型用 `setExactAndAllowWhileIdle`。亮屏时两个时钟的整分都刷，息屏时只跟真太阳时整分（标准时间由宿主的 `TextClock` 自己走），夜里的唤醒次数减半；另有一个 10 分钟一次的兜底闹钟，链条万一被系统清掉也能自己接回来。系统在**覆盖安装／升级**时会清空该包的全部闹钟，而 `updatePeriodMillis` 最晚要 30 分钟才兜底，所以 `RestartReceiver` 同时监听 `MY_PACKAGE_REPLACED`，装完立即补排并整体刷一遍。字号按栏宽实测换算（填满栏宽而不裁切），**且一律用 dp 固定、不跟系统「字体大小」缩放**（桌面单元格尺寸是死的，sp 一旦跟着放大到 1.5～2 倍，版面就会被挤出格子、秒数被裁掉；布局里的 `textSize` 与 `WidgetUpdater` 里的换算全部按 dp）。日期与经纬度那一行是同一档「小字」：卡片里**所有小字统一 11dp、颜色 `#CCFFFFFF`**（与左上角 `UTC+8` 一致：日期行、经纬度、逐时时刻与天气名、日出/正午/日落、城市名与时辰），两者按自然字号算出的总宽超出可用宽度时**一起缩**（下限 0.85），并且字号以 **dp 而不是 px** 下发——桌面进程可能用物理密度（如 P40 Pro 530dpi）而 App 拿到的是「显示大小」覆写后的密度（450dpi），用 px 下发会让这一行比布局里同样标称 11dp 的标签小一圈。**桌面回报的尺寸只是名义值**——普遍按「一格 70dp」折算，实测真实高度约为回报值的 **1.7～2.2 倍**（Pixel 2 格报 116dp／实际 223dp，华为手机 131dp／实际 225dp，华为平板 132dp／实际 288dp），所以版面按折算后的高宽分档，而且**加料只在平板上做**（手机上一加就显满）：**平板且高度 ≥ 240dp** 才加一行「日出 / 正午 / 日落」；**平板且高度 ≥ 255dp、宽度 ≥ 260dp** 再加**第二排逐时天气**（后 6 小时）——平板默认尺寸就满足，所以平板默认是 12 小时预报，手机始终是 6 格；被拖到只剩 1 格时只留两栏时钟与日期，时间轴和逐时行让位，免得内容被裁掉。
- **在设置里一键加卡片**：设置面板的「桌面卡片」区块有「添加到桌面」按钮，走 `AppWidgetManager.requestPinAppWidget()` 弹系统确认框。桌面把卡片放好后会**直接切到桌面前台**，App 进后台，所以结果不是当场判定，而是回到前台（`ON_RESUME`）时比对小组件实例数才落成「已添加到桌面」或「没加上」的提示——请求发出 3 秒内不判定，免得用户还在确认框上。华为桌面在这一屏放不下时只 toast 一句「当前屏幕已经没有空间」（API 仍返回成功），所以失败文案同时给出「腾出一格再试」和「长按桌面 → 窗口小工具」两条路。
- **所在城市／区县**：配置高德 Android 平台 Key 后用 `GeocodeSearch` 反查行政区划（精确到区县）；结果按位置缓存，**新坐标与上次反查坐标相距超过 5 km 才重新查询**，否则一直沿用上次的结果（缓存超过 30 天也会刷新）。**名字跟着界面语言走**：中文界面用高德（西文界面下它只给中文名），其他语言改用 OpenStreetMap 的 Nominatim（`accept-language` 传当前语言，得到 `Huangpu District, Shanghai` / `Mountain View, Santa Clara County, California` 这类写法），失败再退回高德的中文名；缓存里记着当时的语言，**切换语言会自动重查**；换位置（超过 5 km）也会重查，即使桌面上没加小组件（否则首页会一直显示启动时那个默认位置的地名）。不用系统的 `Geocoder`：没有 Google 服务的机型上它不可用，网络不通时还会一直阻塞。未配置 Key、离线或查询失败时回退到内置城市表（省会、常见地级市与各国主要城市取最近，中英双语）。
- **当前天气**：小组件在日期后依次显示当前天气与当天最低/最高气温（例如「11月13日 周五 · 18° 小雨 · 14°~19°」，与首页大卡片同一行结构），底部还有一条**未来 5 小时的小时预报**（每格 1 小时，格内为时刻、天气图标与天气名称：晴／多云／阴／雾／小雨／中雨／大雨／阵雨／雪／大雪／雷雨，夜间图标用倾斜的月牙区分晴与多云）；数据来自 Open-Meteo（无需 Key）：**每 30 分钟取一次数**（或位置移动超过 5 km），而**显示上保留最近 6 小时的数据**——取数失败时（夜间 Doze、闹钟被冻结、刚亮屏网络还没通）继续显示上一次的结果，不会让卡片上的天气整块消失。**换地点后若新地点还没有取得过天气**（缓存属于旧坐标），天气位显示占位符 `--`、逐时框里也显示 `--` 与问号图标，绝不把上一个地点的天气搬过来；手工指定新地点会立刻重取一次，成功后自动换成新地点的读数（几秒内就能看到，不必等大卡片半分钟的刷新节拍——天气缓存写完后首页会按版本号立即重算）。
- **进入关键时间报时**：可开关，每到一段**关键时间的起点**蜂鸣一次，时长 500 ms（与时辰交接的 250 ms 区分开）、频率 **3200 Hz**（自己合成正弦波并加 10 ms 淡入淡出，比系统提示音高而清楚；`AudioTrack` 不可用时退回 `ToneGenerator` 的高频 pip）。关键时间按真太阳时计，报时闹钟也按真太阳时刻度对齐后再换算成系统时刻交给 `AlarmManager`，所以**锁屏与休眠时也会准时响**；接收器用 `goAsync()` 保活到播放结束，避免进程被回收把声音截断。**华为/荣耀**上 PowerGenie 会冻结后台应用并代理其广播（日志里的 `proxyBroadcast: proxy:true` + `perform delay action`），普通精确闹钟会被推迟到应用解冻才投递，因此这两家改用 `setAlarmClock()` 排程（实测触发瞬间解冻并正常投递，代价是状态栏出现闹钟图标）；**小米/红米/HyperOS** 也存在同类问题（见「桌面小组件」一条），一并走 `setAlarmClock()`。其他机型仍用 `setExactAndAllowWhileIdle`、没有图标。设置面板里还提供了「报时没响？点此允许本应用后台运行」的直达入口。另需注意：Android 13+ 不再默认授予 `SCHEDULE_EXACT_ALARM`，缺少该权限时只能退化为可延迟闹钟（可能晚几分钟）；打开报时开关时若发现未授权会自动跳到「闹钟和提醒」页，设置里也会显示红色提示。只响提示音，不发通知、不占通知栏；音量跟随**通知音量**，静音或勿扰模式下不会响。没有关键时间数据（从未抓取成功或已超过 7 天）时不报时。
- **小组件点击**：点左侧标准时间打开系统闹钟，点日期打开系统日历（`CATEGORY_APP_CALENDAR` → `content://com.android.calendar/time`），点底部天气打开系统天气（`CATEGORY_APP_WEATHER` → 常见厂商包名 → 浏览器兜底），点右侧真太阳时打开本 App。外部应用的解析结果缓存 10 分钟，且在 Manifest 里用 `<queries>` 声明可见性（Android 11+ 必需）。
- **小组件显示「加载失败」怎么办**：那是系统的 **stopped 状态**在起作用，不是小组件自己崩了。刚装好还没打开过 App、在设置里「强行停止」过、或被省电策略清理掉的包会进入 stopped 状态，Android 会把它的所有小组件屏蔽（桌面只剩灰色占位或时钟图标），日志里是 `AppWidgetServiceImpl: Updating package stopped masked state … isStopped true`，同时该包的闹钟也会被清空。**打开一次 App 即恢复**（启动时会整体重绘并重排刷新闹钟）。因此安装后请先打开一次；国产 ROM 上还要允许它后台运行，别把「强行停止」当清理手段。另外刷新过程中任何一步出错都会退化成「只显示时:分」的最小版面，不会再整块变成加载失败。
- **关键时间时间轴**：天气上方那道横线是真太阳时 **0–24 时**的时间轴，轴线铺满卡片内容宽度、两端与上面的日期行／右上角经纬度对齐（整条轴连同圆点都按位图贴上去，不做左右内缩；只有当前时刻正好在 0:00／24:00 时圆点会被卡片边缘裁掉一半，与首页那版一致），白点（边缘做了柔化）标出当前时刻——**这个点子的纵向是锁死的**（API 31+ 用 `setViewLayoutHeight` 把轴视图高度钉成位图的像素高度，免得宿主按自己的密度换算 `13dp` 时把圆点拉成竖椭圆），**横向则只在平板上按桌面的拉伸预先压扁**（`WidgetUpdater.dotXCompensation()`：手机桌面回报的宽度与真实卡片基本一致，保持原样；华为平板回报 304dp 而实际卡片约 396dp，不补偿就会被拉扁）；轴上按「西格瑪食療」页面（<https://www.duosuccess.com/tcm/001a01080301b01a.htm>）上的「服用時間 Take Time」着色，页面给的时间就当作**关键时间**——**视作真太阳时**，不做时区或经度换算；标注 **Cold or Mild 用绿色**、**Hot or Mild 用红色**，色带与轴线等宽（只换颜色，不抢眼）。页面每天在 **01:00–05:00 之间挑一个随机时刻**同步一次，失败每小时重试；结果连时间戳一起缓存，**7 天内打不开就沿用上次的数据**，超过 7 天或从未成功抓取过则只画轴线、不着色。整条轴在 App 进程里画成位图后用 `setImageViewBitmap` 贴上去（`WidgetAxis`），因为没有能随刷新改变位置的系统控件可用。
- **添加到桌面**：从桌面添加（长按空白处 →「小组件」→ 真太阳时）。设置面板里原来那个「添加桌面小组件」按钮已经移除——Android 没有「新建桌面页」的公开 API，桌面上没有空位时它只能弹一句提示，体验反而更差。
- **竖屏锁定**：两版都只支持竖屏（Android 在 Manifest 里把 `MainActivity` 钉成 `screenOrientation="portrait"`，鸿蒙在 `module.json5` 里给 `EntryAbility` 写 `"orientation": "portrait"`）——布局本来就是竖排单列，横过来只会被拉扁。
- **屏幕常亮**：设置面板里可开关，**默认打开**；打开 App 期间不自动熄屏（Android 加窗口标志 `FLAG_KEEP_SCREEN_ON`，鸿蒙调 `setWindowKeepScreenOn`）。只在前台有效，退到后台后系统照旧按自己的休眠时间熄屏，不会额外耗电。
- **多语言**：跟随系统语言自动切换简体中文、繁体中文或英文（`values-zh` / `values-b+zh+Hant` / `values`）。
- **主题**：白天／夜间两套主题，按太阳高度角自动切换（不看系统的深色开关）。白天是浅色纸面（米白底 + 白卡片 + 深字），首页大卡片为暖橙底 + 白字，其中**真太阳时用淡金**（`#FFE6B4`，比纯白暖一档，和标准时间区分开）；夜里整体换深色（#0B1220 底 + #16203A 卡片 + 浅字），大卡片为深蓝底 + 金字。关键时段的配色也分两档、分两种用途：**真太阳时数字**白天用与淡金同浓度的淡绿 `#BCF5CA`／淡红 `#FFC4C9`（深绿／深红压在橙底上发闷），夜里用较亮的绿 `#4CAF7D`／红 `#D9534F`；**时间轴上的色段与圆点**白天仍用深一档的 `#2E7D32`／`#B3261E`（淡色在橙底上几乎看不出边界），夜里与数字同色。Android 与鸿蒙同一套取值。

## 计算原理

```
真太阳时 = 北京时间 + (当地经度 − 120°) × 4 分钟 + 均时差
```

- **经度修正**：经度每偏离东经 120°（东八区中央经线）1°，时间相差 4 分钟。
- **均时差**：地球轨道偏心率与黄赤交角造成的日差，全年在约 −14 分到 +16 分之间变化，采用 NOAA Solar Calculator 的算法，误差约 ±0.5 分钟。
- **日出日落**：按天顶角 90.833°（含大气折射与太阳视半径）求解时角。

### 左栏「标准时间」用的是哪个时区

真太阳时与钟表的差值要靠一个基准时区来读，所以左栏那个时钟显示的是**观测点所在地的法定标准时**，标签直接写成 `UTC+8` / `UTC-5` 这种形式（中国境内就是北京时间，与手机时钟一致）：

- **中国境内**（经度 73–135、纬度 18–54，含港澳台）**恒为 UTC+8**，不按经度算——否则乌鲁木齐 87°E 会被算成 UTC+6。
- **境外**：逆地理编码顺带取回国家码，已知国家查表；美国、俄罗斯、加拿大、澳大利亚、巴西、墨西哥、印尼、哈萨克这类多时区大国按经度分段（如纽约 −5、洛杉矶 −8、莫斯科 +3、符拉迪沃斯托克 +10）；表里没有的国家按 `round(经度 / 15)` 取整。
- 拿不到国家码（未联网、没配高德 Key、刚启动）时按经度取整兜底，中国境内仍然正确；缓存里的国家码只在坐标没跑远（50 km 内）时才算数，否则「从上海手工切到纽约、这次反查又失败」会把纽约算成 UTC+8。
- **不处理夏令时**（存的是标准时，与鸿蒙版同一口径）；只有「设备时区恰好与观测点的标准偏移一致」时才直接用设备时区，顺带照顾到人在当地的情况。

以北京（东经 116.4074°）11 月 2 日为例：经度修正 −14 分 22 秒，均时差 +16 分 29 秒，真太阳时比北京时间快约 2 分 06 秒。

## 构建

仓库按目标平台分目录，Android 部分在 `android/`：

```
android/   Android 工程（Kotlin + Compose，Gradle 根目录）
ios/       iPhone 工程（SwiftUI），见 ios/README.md
harmony/   鸿蒙工程（ArkTS + ArkUI），见 harmony/README.md
```

Android 侧需要 JDK 17+ 与 Android SDK（compileSdk 35、build-tools 35.0.0）。

```bash
cd android
./gradlew assembleDebug        # 产出 android/app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest    # 太阳时／时辰计算单元测试
./gradlew lintDebug
./gradlew assembleRelease      # 产出 android/app/build/outputs/apk/release/app-release.apk
```

`assembleRelease` 结束后会自动把产物另存为 `android/dist/真太阳时-<版本号>.apk`（如 `真太阳时-1.4.5.apk`），
可直接分发；`dist/` 不参与版本控制，也不受 `clean` 影响。

发行版签名读取 `android/keystore.properties`（**不入库**），格式：

```properties
storeFile=release.jks
storePassword=***
keyAlias=solartime
keyPassword=***
```

缺少该文件时 `assembleRelease` 会产出未签名 APK。

可选：`android/amap.properties`（同样**不入库**）配置高德 **Android 平台 Key**，用于小组件显示区县名：

```properties
apiKey=你的高德Android平台Key
```

申请时填写的应用信息：

| 项 | 值 |
| --- | --- |
| PackageName | `com.realsuntime.solartime` |
| 发布版安全码 SHA1 | 见 `keytool -list -v -keystore android/release.jks -alias solartime` |
| 调试版安全码 SHA1 | 见 `keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android` |

Key 会作为 `com.amap.api.v2.apikey` 元数据打进 Manifest，只在逆地理编码时使用；不配置时小组件用内置城市表。配置后，只有新坐标与上次反查坐标相距 **超过 5 km**（或缓存超过 30 天）时才查询一次高德——市中心日常移动基本不会触发，配额压力极小（Android 平台 Key 与包名、签名绑定，他人反编译也无法使用）。

## 图标

图标是一只**倾斜 45° 的椭圆表盘**（圆盘按 41° 视角投影），指针枢轴位于椭圆偏下方的焦点处，刻度沿盘缘排布且每一根都指向枢轴。表圈、指针、中心轴帽均为解析式 3D 着色（Lambert + Blinn-Phong 高光、接触阴影、指针棱线）。

图标由脚本生成，不要手改 PNG：

```bash
python design/render_icon.py all       # 生成全部尺寸（Android mipmap/自适应图层、商店图标、iOS AppIcon）
python design/render_icon.py preview   # 生成 design/drafts/ 下的草稿便于调参
```

- `design/render_icon.py`：渲染器，参数集中在 `DEFAULTS`（倾角 `tilt_deg`、枢轴位置 `pivot_frac`、指针角度等）
- `design/icon-1024.png`、`design/icon-512.png`：母版与商店上传图
- 自适应图标：`mipmap-anydpi-v26/ic_launcher.xml` 引用 `ic_launcher_background.png` + `ic_launcher_foreground.png`（前景按 66dp 安全区缩放）
- 主题图标（Android 13+ 单色）：`drawable/ic_launcher_monochrome.xml`
